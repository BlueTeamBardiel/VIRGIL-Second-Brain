# Cisco IOS CLI

## What it is

The Cisco IOS CLI is the command line you drop into when you jack into a Cisco router or switch — closer to a netrunner's deck in Cyberpunk 2077 than to a fancy GUI. There's no mouse, no dashboard, just a blinking prompt that judges your spelling. Everything that happens on the box — interfaces coming up, routes being added, passwords being set — is typed in by hand or pasted from a config file.

To get into that prompt the first time (before the device has any IP config), you plug a console cable into it and open a terminal emulator like **PuTTY**. PuTTY is the launcher: same app, two doors — a serial door for the physical console cable, and an SSH door for remote sessions once the device is on the network.

The CLI itself is split into **modes**, like ability tiers in a soulslike. Each mode unlocks a different set of verbs:

- **User EXEC Mode** — `Router>` — the tutorial zone. You can look around and run pings, but you can't change anything.
- **Privileged EXEC Mode** — `Router#` — admin tier. Reached by typing `enable`. You can view everything and run powerful diagnostics.
- **Global Configuration Mode** — `Router(config)#` — the build menu. Reached from privileged mode with `configure terminal` (or `conf t` for people who type for a living). This is where you actually change the device.

## Why it matters

Every Cisco-flavored network on the planet — ISPs, enterprise cores, your CCNA lab — speaks this dialect. Knowing the CLI is the difference between *being able to fix the network* and *filing a ticket and waiting*.

The mode system also matters because it's your guardrail. User EXEC is the equivalent of spectator mode in Among Us — you can watch, you can't vote anyone out. That separation prevents a junior who only needed to check an interface from accidentally shutting down a core link. The `enable` step is the deliberate "yes, I meant to do that" gate.

And the running-config vs startup-config split is the part that bites everyone exactly once: change something, forget to save, reboot the device, watch your work evaporate. Like grinding loot in Tarkov and forgetting to extract.

## Key facts

### Getting connected

- **PuTTY** handles both serial console sessions and SSH sessions to Cisco gear.
- Cisco's default console serial settings: **9600 bps, 8 data bits, 1 stop bit, no parity, no flow control**. If your terminal shows garbage, one of these five is wrong — it's almost always the baud rate.

### The three modes (the prompt tells you where you are)

- `Router>` — User EXEC. View-only, basic diagnostics. Like browsing a Steam library you don't own — you can read, you can't launch.
- `Router#` — Privileged EXEC. Entered with `enable`. Full visibility, full diagnostic toolkit, can save configs.
- `Router(config)#` — Global Configuration. Entered from privileged with `configure terminal` / `conf t`. This is where edits happen.

### Passwords (and why most of them are theater)

- `enable password` — stores the password in **clear text**. Anyone with `show running-config` reads it like a Discord message.
- `enable secret` — stores the password as an **MD5 hash**. Cracking it takes real effort.
- **Three consecutive failed `enable` attempts** lock out further attempts.
- `service password-encryption` — encrypts *all* passwords in the config except `enable secret` (which is already hashed) using **Type 7 encryption**.
- **Type 7 is trivially crackable** — there are websites that decode it instantly. It's the "Player1" Wi-Fi password of encryption schemes. It only stops shoulder-surfing, not a real attacker.
- Turning `service password-encryption` *off* does **not** decrypt passwords that were already encrypted. The toggle only affects what happens going forward.

### Running-config vs Startup-config

- **Running-config** — the live configuration in RAM. Every change you make in config mode hits this immediately. Volatile — disappears on power loss.
- **Startup-config** — stored in NVRAM. This is what loads on reboot.
- `show running-config` — displays the active config.
- `show startup-config` — displays the config that will load next reboot.
- Save commands (all do the same thing): `write`, `write memory`, `copy running-config startup-config`. The classic "remember to hit save before you alt-F4" moment.

### CLI editing shortcuts

- **Backspace / Delete** — erase one character.
- **Ctrl + U** — wipe the entire current line. The "no, I'm starting over" button.
- **Ctrl + C** — abort the command before it executes. Panic eject.
- **Ctrl + Z** — bail out of config mode straight back to privileged EXEC. Like hitting Escape twice in a menu.

### Useful command modifiers

- `no <command>` — undoes a previously configured command. `shutdown` turns an interface off; `no shutdown` turns it back on. The universal undo.
- `do <command>` — runs a privileged EXEC command from inside global configuration mode without leaving. Lets you `do show running-config` mid-edit instead of bouncing out and back in. Pure quality-of-life, like fast-traveling without closing the map.
