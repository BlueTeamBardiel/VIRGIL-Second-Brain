# WPA3-802.1X

## What it is

A Discord server with a public invite link versus a Discord server where every member has their own verified account, role, and audit log entry. WPA2-PSK and WPA3-Personal are the public link — one shared secret, everyone uses it, and if someone leaks it, the whole server is cooked. WPA3-802.1X is the verified-account version: every user authenticates individually against a central authority, gets their own session keys, and can be kicked without nuking everyone else's access.

Technically, WPA3-802.1X is the **enterprise mode of WPA3**. Instead of a pre-shared key, every connecting device proves its identity to a **RADIUS server** using the 802.1X framework and an EAP (Extensible Authentication Protocol) method. WPA3-802.1X keeps the modern crypto upgrades from WPA3 — SAE-based key establishment, forward secrecy, stronger ciphers — and bolts them onto 802.1X's per-user authentication model.

## Why it matters

When the **KRACK attack** dropped in 2017, it weaponized flaws in WPA2's 4-way handshake by replaying messages to force nonce reuse. PSK deployments got mauled. Enterprise deployments running 802.1X with mutual authentication held up better because the attacker couldn't just sit on a coffee shop SSID and capture a handshake to crack offline — there was no shared passphrase to grind on.

WPA3-802.1X takes that hardening further. There is **no passphrase**, so offline cracking is meaningless. The static PMK concept that enabled **PMKID attacks** in WPA2 is gone. **Forward secrecy** means even if an attacker compromises a server's long-term key tomorrow, last month's captured traffic stays unreadable — like Snapchat messages that actually delete instead of sitting in a database waiting to leak.

For environments where "the wifi password got posted in a group chat" is a career-ending event — government, finance, anywhere with a real threat model — WPA3-802.1X with its 192-bit mode is the baseline.

## Key facts

### Authentication model
- **Per-user identity**: Each user authenticates to a RADIUS server with their own credentials, certificate, or token. Like every raider in Escape from Tarkov having their own account — getting one banned doesn't ban the lobby.
- **RADIUS server is mandatory**: No RADIUS, no WPA3-Enterprise. The RADIUS server is the bouncer with the guest list.
- **Individual revocation**: Fire someone, revoke their cert. Everyone else keeps working. No mass password rotation panic.

### Supported EAP methods
- **EAP-TLS**: Certificate-based, mutual authentication, strongest of the bunch. Both client and server prove identity with certs — like a two-way handshake where both sides show ID.
- **PEAP**: Tunnels weaker inner auth (usually MSCHAPv2) inside a TLS tunnel. Server cert only; client uses username/password inside the tunnel.
- **EAP-TTLS**: Similar to PEAP — TLS tunnel protecting inner auth, more flexible on inner methods.

### Cryptographic guarantees
- **SAE with forward secrecy**: Even WPA3-Enterprise leverages SAE-style key establishment so each session key is independent. Capturing ciphertext now and stealing keys later doesn't retroactively decrypt anything.
- **No static PMK**: Kills PMKID-style offline attacks dead. Watch Dogs 2 vibes — the exploit just doesn't have a foothold to grab.
- **No passphrase to crack offline**: There's nothing for an attacker to take home and brute-force on a GPU rig.

### 192-bit security mode (WPA3-Enterprise's hard mode)
- **Mandatory for U.S. government networks** and recommended for finance and other high-assurance environments.
- **AES-256-GCMP** for bulk encryption — 256-bit key, authenticated encryption mode.
- **HMAC-SHA-384** for key derivation and integrity.
- Suite-B aligned crypto across the stack — no weak link where someone slipped 128-bit AES in next to a 384-bit hash.

### KRACK context
- 2017's KRACK exploited the WPA2 4-way handshake by replaying handshake messages to coerce key/nonce reuse.
- WPA2-Enterprise with mutual EAP auth resisted parts of the attack better than WPA2-PSK.
- WPA3's redesigned handshake (Dragonfly/SAE) closes the replay-induced nonce reuse class of bug entirely.
