# 13. Spanning Tree Protocol

## What it is

Three Discord servers all set to auto-forward every message to each other — Beatrice posts "hi" once, and within seconds the same "hi" is bouncing between all three servers forever, pinging everyone into oblivion. That's an Ethernet loop. Switches, by design, flood broadcast, unknown unicast, and multicast frames out every port except the one they came in on. Wire two switches together with two cables and you've built a perfect echo chamber: one broadcast frame circles forever, MAC tables flip back and forth as the same source address shows up on different ports, and CPUs cook themselves trying to keep up.

Spanning Tree Protocol (STP, IEEE 802.1D) is the referee that prevents this. Switches talk to each other using a control frame called a **BPDU** (Bridge Protocol Data Unit), elect one switch as the **Root Bridge**, calculate the cheapest path from every other switch back to that root, and then deliberately **block** any port that would create a loop. The redundant cables stay physically plugged in — they just sit on the bench like a sub on an NBA 2K26 roster, ready to come in if a starter goes down.

The result is a "spanning tree": a loop-free subset of the physical topology that still touches every switch.

## Why it matters

Redundant links are non-negotiable in any real network — you want a second cable between your core switches the same way Helldivers 2 squads want a second Eagle stratagem queued up. But Layer 2 has no TTL field. Unlike IP packets, an Ethernet frame has no hop counter to kill it. One loop and your network doesn't slow down — it dies. Switch CPUs spike to 100%, MAC tables thrash, and legitimate traffic stops moving entirely. The only fix without STP is unplugging cables until you find the loop.

STP gives you the redundancy without the meltdown: backup links stay live at the port level, ready to unblock and forward in roughly **50 seconds** when a primary link fails. Slow by modern standards, but infinitely better than a melted broadcast storm.

## Key facts

### Vocabulary
- **Bridge** = switch (the spec is older than the word "switch")
- **Segment** = a Layer 2 link between two devices
- **Collision domain** = one per switch port in modern full-duplex Ethernet
- **Spanning tree** = the loop-free subset of links STP carves out of your physical topology

### Root Bridge Election
- The switch with the **lowest Bridge ID (BID)** wins and becomes root — like the lowest-numbered seed in a bracket
- **BID = 16-bit priority + 48-bit MAC address** (64 bits total)
- Default priority is **32768**
- Tie-breaker: lowest MAC address wins (so the oldest switch in the closet often becomes root by accident — set priority manually)
- **PVST+** (Cisco's per-VLAN flavor) splits the 16-bit priority into a 4-bit configurable priority + 12-bit VLAN ID, so root election can differ per VLAN

### Path Cost (cost is inverse to speed — faster pipe, cheaper toll)
| Link Speed | STP Cost |
|---|---|
| 10 Mbps | 100 |
| 100 Mbps | 19 |
| 1 Gbps | 4 |
| 10 Gbps | 2 |

Total path cost from a switch to the root = sum of the costs of every link along the way.

### Port Roles (every port gets one job)
- **Root Port (RP)**: the one port on a non-root switch with the cheapest path back to root. Forwards.
- **Designated Port (DP)**: one per segment — the port that wins the right to forward on that link. The root bridge's ports are all designated.
- **Non-Designated / Blocked Port**: the loser. Sits and listens to BPDUs but forwards nothing. This is the bench player keeping the network loop-free.

### Root Port tie-breakers (in order)
1. Lowest root path cost
2. Lowest sending switch's BID
3. Lowest sending port ID

### Port States (the boot-up onboarding flow)
Like a new player going through tutorial gates in Elden Ring before they're allowed into the open world:

- **Disabled** — admin shut it down. Nothing happens.
- **Blocking** — receives BPDUs only. No forwarding, no MAC learning.
- **Listening** (15s, set by Forward Delay) — sends and receives BPDUs, still no forwarding, no learning. Figuring out its role.
- **Learning** (15s) — starts populating its MAC table but still won't forward frames yet.
- **Forwarding** — fully active. Forwards frames, learns MACs, exchanges BPDUs.

### Timers (all set on the root, pushed to everyone)
- **Hello** = 2 seconds — root sends a BPDU every 2 seconds, like a heartbeat ping
- **Forward Delay** = 15 seconds — duration of Listening AND Learning each
- **Max Age** = 20 seconds — how long a port waits after BPDUs go silent before recalculating

**Convergence math when a forwarding link dies: 20 + 15 + 15 = ~50 seconds.** That's why Rapid STP exists.

### BPDUs
- Control frames switches use to elect the root, share topology, and assign port roles
- **Never carry user data** — pure signaling, like the in-game voice channel vs. the actual gameplay
- IEEE 802.1D destination MAC: **0180.c200.0000**
- Cisco PVST+ destination MAC: **0100.0ccc.cccd**
- **Routers do not forward BPDUs** — Layer 3 boundaries stop the spanning tree
- On boot, every switch sends BPDUs out every port claiming to be root (cocky)
- After convergence, only the **root bridge originates BPDUs**; other switches just relay them out their designated ports
- Root ports and blocked ports **receive** BPDUs but never forward them
- Blocked ports still listen — if the network topology changes, they can transition back through Listening → Learning → Forwarding to take over
