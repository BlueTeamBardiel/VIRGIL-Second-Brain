# Router and Switch Interfaces

## What it is

A switch port is like a seat at a Discord voice channel — every device plugged in gets a spot, and the switch decides who hears whom. But not all switches let you tweak the seating chart.

An **unmanaged switch** is the IKEA-furniture version: plug stuff in, frames move, done. No config, no VLANs, no logging in. You buy it, you forget it exists.

A **managed switch** is the full mixing console — you SSH in and configure VLANs, QoS, port security, speed, duplex, descriptions, and a hundred other knobs. This is what you'll actually touch in any serious network.

Each physical port on a managed switch (or router) is an **interface**, and most of your job as an admin is naming them, enabling them, watching their counters, and figuring out why one of them is throwing CRC errors at 3 AM.

## Why it matters

A misconfigured interface is the networking equivalent of a controller with stick drift in Elden Ring — the game technically runs, but you're losing fights for reasons that look invisible from the outside. A duplex mismatch won't take a link down; it'll just silently bleed throughput while users complain that "the internet is slow." Knowing how to read interface output is how you stop guessing and start diagnosing.

Router interfaces being **administratively down by default** is also a gotcha that bites every beginner — you cabled it up, the light is on, and nothing works because nobody told the interface it was allowed to wake up.

## Key facts

### Naming and bulk config
- **`description WAN_to_Limbo_Capital`** — slaps a text label on an interface so future-you doesn't have to trace a cable. Like renaming "New Folder (47)" to something useful.
- **`interface range gi1/0/1 - 24`** — configures 24 ports in one shot. The "select all" of IOS.
- **`show interfaces description`** and **`show interfaces status`** — pulls up your labels so you can find that one port without crawling under the desk.

### Speed
- Interface speed = max bits per second the port can push: 10 Mbps, 100 Mbps, 1 Gbps, 10 Gbps, etc.
- **`speed 1000`** — hard-codes the speed and disables autonegotiation on that interface.
- **Autonegotiation** is the handshake where two devices compare capability sheets and pick the best speed + duplex they both support — basically Tarkov's matchmaking trying to find a lobby both players can run.

### Duplex
- **Half-duplex** = walkie-talkie. One side talks, the other waits. Collisions are expected.
- **Full-duplex** = phone call. Both sides talk simultaneously, no collisions possible.
- 10 Mbps and 100 Mbps Ethernet default to **half-duplex**.
- 1 Gbps and faster default to **full-duplex** (the spec basically requires it at those speeds).

### Autonegotiation failure defaults
- 10/100 Mbps devices fall back to **half-duplex** when negotiation fails.
- 1000 Mbps devices often fall back to **10 Mbps half-duplex** — a brutal downgrade, like getting kicked from a ranked Apex lobby into a 56k modem.

### Speed mismatch vs duplex mismatch
- **Speed mismatch** → interface goes **Down/Down**. No link, no traffic, obvious problem. The cable might as well be unplugged.
- **Duplex mismatch** → interface stays **Up/Up**, traffic flows, but you get collisions, late collisions, CRC errors, retransmissions, and trash throughput. This is the silent killer — like lag compensation working against you in CoD. Everything looks fine until you check the counters.

### Interface state commands
- **`shutdown`** — admin disables the port. The "do not disturb" mode.
- **`no shutdown`** — re-enables it. Required on every router interface out of the box because routers ship with all interfaces administratively down.
- **err-disabled** — the port self-quarantined because something tripped a threshold (port security violation, BPDU guard, excessive errors). Like getting shadowbanned — the port is up physically but refuses to forward.

### Reading the counters
- **`show interfaces`** — full dump per port: speed, duplex, errors, drops, load. Your main diagnostic tool.
- **`show ip interface brief`** — router-favorite. One line per interface: IP, status, protocol. The dashboard view.
- **Runts** — frames smaller than 64 bytes. Truncated, malformed, or collision fragments.
- **Giants** — frames larger than 1518 bytes (jumbo frames excepted). Oversized garbage.
- **CRC errors** — frame arrived with a bad checksum. Bit got flipped somewhere — usually cabling, EMI, or duplex mismatch.
- **Input errors** = runts + giants + CRC + frame errors, totaled for inbound traffic.
- **Output errors** = frames that failed going out.
- **Collisions** — should be **zero** on a modern full-duplex switched link. Any non-zero count means something's wrong.
- **Late collisions** — collisions detected after the first 64 bytes were already transmitted. On a properly sized full-duplex segment this is impossible, so seeing them is a near-certain fingerprint of a **duplex mismatch** (one side is full-duplex blasting whenever it wants, the other side is half-duplex and treating those transmissions as collisions).

### The diagnostic shortcut
- Up/Up but slow + climbing late collisions + CRC errors → **duplex mismatch**, every time.
- Down/Down → **speed mismatch**, bad cable, or the other side is shut down.
