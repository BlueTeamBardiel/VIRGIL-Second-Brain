# 802.1X Port-Based Network Access Control

## What it is

In League of Legends, before you load into a ranked match, the client checks your account, your champion ownership, and your queue eligibility — you don't get to walk onto Summoner's Rift just because you clicked "Find Match." The matchmaking server vouches for you to the game server before the loading screen even appears. That's exactly what **802.1X** does — it forces a device to prove who it is before the switch port lets a single useful frame through.

**802.1X** is an IEEE standard for **Port-Based Network Access Control (PNAC)** that authenticates devices at Layer 2 before granting access to the LAN, using EAP encapsulated over LAN (EAPoL) between client and switch, and RADIUS between switch and authentication server.

## Why it matters

Without 802.1X, anyone who finds an unused Ethernet jack in a conference room or hijacks an SSID owns a port on your network — no credentials required, no questions asked. With it, an unauthenticated device sits in a controlled-port purgatory where only EAPoL traffic passes, and a misconfigured RADIUS server or expired certificate means *nobody* gets on the network. **Exam angle:** know the three roles, the EAPoL flow, and that 802.1X is the foundation of the [[CCNA 200-301]] security domain alongside [[port security]] and [[DHCP snooping]].

## Key facts

### The three roles

| Role | Who plays it | Job |
|------|-------------|-----|
| **[[Supplicant]]** | The endpoint (laptop, phone, IP phone) | Sends credentials via EAP |
| **[[Authenticator]]** | The switch or wireless AP | Relays EAP between supplicant and server; enforces port state |
| **[[Authentication Server]]** | A [[RADIUS]] server (e.g., [[Cisco ISE]], FreeRADIUS) | Validates credentials, returns accept/reject |

The authenticator is a **dumb middleman**. It does not know or care what the credentials are — it only knows whether the RADIUS server said yes.

### EAPoL flow (wired)

1. **EAPoL-Start** — supplicant announces itself (or switch sends EAP-Request first).
2. **EAP-Request/Identity** — authenticator asks "who are you?"
3. **EAP-Response/Identity** — supplicant answers; switch wraps it in [[RADIUS Access-Request]].
4. **RADIUS challenge/response** — EAP method runs ([[EAP-TLS]], [[PEAP]], [[EAP-FAST]], etc.).
5. **RADIUS Access-Accept** (or Reject) — switch transitions controlled port to authorized.
6. **EAPoL-Logoff** — supplicant tears down the session.

### Port states: uncontrolled vs controlled

Every 802.1X-enabled port is logically two ports:

- **Uncontrolled port** — always open, but only passes [[EAPoL]] frames (EtherType `0x888E`). This is how authentication traffic flows before authorization.
- **Controlled port** — blocks all data traffic until authentication succeeds. After Access-Accept, it transitions to **authorized** and forwards normally.

Default state of the controlled port: **unauthorized** (force-unauthorized blocks everything; force-authorized disables 802.1X on that port; **auto** is the real-world setting).

### Cisco IOS configuration

```
aaa new-model
aaa authentication dot1x default group radius
aaa authorization network default group radius
dot1x system-auth-control

radius server ISE
 address ipv4 10.1.1.10 auth-port 1812 acct-port 1813
 key 7 <shared-secret>

interface GigabitEthernet0/1
 switchport mode access
 authentication port-control auto
 dot1x pae authenticator
```

Verify with:
```
show dot1x interface Gi0/1 details
show authentication sessions
```

### Port numbers and protocols

- **EAPoL** — EtherType `0x888E`, runs directly on Ethernet (no IP).
- **RADIUS** — UDP `1812` (auth) and `1813` (accounting). Legacy: `1645`/`1646`.
- **EAP methods** — EAP-TLS (cert-based, strongest), PEAP (server cert + inner MSCHAPv2), EAP-FAST (Cisco PAC-based).

### Wired vs Wi-Fi

| | Wired LAN | Wireless |
|---|---|---|
| Authenticator | Access switch | [[WLC]] or autonomous AP |
| Trigger | Link-up on port | Association to SSID |
| Encryption tie-in | None (port just opens) | Derives PMK → 4-way handshake → per-session keys ([[WPA2-Enterprise]] / [[WPA3-Enterprise]]) |

On Wi-Fi, 802.1X is the "Enterprise" half of WPA2/WPA3 — the alternative to a [[PSK]].

### Failure modes worth knowing

- **No supplicant on device** (printers, old IoT) → use [[MAB]] (MAC Authentication Bypass) as fallback.
- **RADIUS server unreachable** → configure a **critical VLAN** or `authentication event server dead action authorize`.
- **Authentication failed** → optionally drop into a **guest VLAN** or **auth-fail VLAN**.
