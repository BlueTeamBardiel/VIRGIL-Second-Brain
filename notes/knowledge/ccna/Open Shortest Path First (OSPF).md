# Open Shortest Path First (OSPF)

## What it is

OSPF is the GPS app of routing protocols. Instead of each router asking its neighbors "hey, how far is it to the grocery store?" and trusting whatever number they shout back (that's how distance-vector protocols like RIP work — pure gossip), OSPF builds a full topological map of the entire neighborhood. Every router learns the shape of the whole network, then runs Dijkstra's shortest-path-first algorithm locally to compute the best route — like a Tears of the Kingdom map after you've activated every Skyview Tower.

OSPF is a **link-state Interior Gateway Protocol (IGP)**. Routers don't trade routing tables; they trade descriptions of links — "I'm router X, I'm connected to subnet Y at cost Z." Every OSPF router stores these descriptions in a **Link State Database (LSDB)**, and every router in the same area must hold an identical copy. Once the LSDB is in sync, each router independently runs Dijkstra against it to figure out the cheapest path to every destination.

## Why it matters

When a link goes down in a distance-vector network, routers play telephone — slowly, hop by hop, propagating the bad news while loops form and packets get black-holed. OSPF doesn't do that. A single router floods a Link State Update, every router patches its LSDB, and they all recompute only the routes affected by the change. It's the difference between a Discord server where one mod posts an announcement to #general versus a chain text where Beatrice tells Dante, who eventually tells Virgil three hours later.

The tradeoff: OSPF eats more CPU (Dijkstra isn't free) and more bandwidth on initial sync (the whole LSDB has to be exchanged). But once it's running, steady-state updates are tiny — just deltas, only when something changes. For any network bigger than a closet, that tradeoff is worth it.

## Key facts

### Core mechanics
- **Algorithm**: Dijkstra's SPF, computed locally against the LSDB.
- **Metric**: Cost, derived from bandwidth. Formula: `Reference Bandwidth ÷ Interface Bandwidth`. Default reference bandwidth is **100 Mbps**.
- **Max network diameter**: 65,535 hops — effectively unlimited.
- **Path selection**: Lowest total cost (sum of outbound interface costs along the path).
- **Transport**: Runs directly on **IP protocol 89** — not TCP, not UDP. OSPF is its own Layer 4-ish citizen.
- **Multicast addresses**: Hellos go to **224.0.0.5** (AllSPFRouters); DR/BDR-specific traffic uses 224.0.0.6.

### Cost examples (default reference bandwidth)
| Interface | Cost |
|---|---|
| Loopback | 0 |
| FastEthernet (100 Mbps) | 1 |
| Gigabit Ethernet (1 Gbps) | 1 ← bug, not feature |
| T1 (1.544 Mbps) | 64 |
| 56k serial | 1,785 |

That Gigabit-equals-FastEthernet problem is why you bump the reference bandwidth globally on modern networks — otherwise OSPF can't tell a 1G link from a 100G link.

### Areas — the OSPF zoning system
Areas are like the regions in Elden Ring: each one has its own internal map, but you cross between them through specific gates (ABRs).

- **Area IDs are 32-bit numbers**, often written like IPs (0.0.0.0).
- **Area 0 is the backbone**. Every other area must touch it. No exceptions, no shortcuts.
- **Stub area**: blocks Type 5 (external) LSAs.
- **Totally Stubby**: blocks Type 3, 4, and 5 — only a default route gets in.
- **NSSA (Not-So-Stubby Area)**: stub-like, but allows external routes via **Type 7 LSAs**, which the ABR rewrites into Type 5 LSAs when leaving the NSSA.

### Router roles
- **Internal Router**: all interfaces in one area.
- **Backbone Router**: at least one interface in Area 0.
- **ABR (Area Border Router)**: connects an area to Area 0.
- **ASBR (Autonomous System Border Router)**: the diplomat — connects OSPF to a foreign routing domain (BGP, EIGRP, static redistribution).

### Packet types (the five OSPF message types)
1. **Hello** — keepalive and neighbor discovery.
2. **DBD (Database Description)** — "here's a summary of what I know."
3. **LSR (Link State Request)** — "send me the full version of these entries."
4. **LSU (Link State Update)** — the actual LSAs.
5. **LSAck** — "got it." OSPF is reliable on top of IP because it acks its own updates.

### LSA types (the actual map fragments)
- **Type 1 (Router LSA)** — every router floods one inside its area. Stays in-area.
- **Type 2 (Network LSA)** — generated by the DR on multi-access segments. Stays in-area.
- **Type 3 (Network Summary)** — generated by ABRs, crosses area boundaries. "Here's what's in the next area over."
- **Type 4 (ASBR Summary)** — generated by ABRs, advertises *where* the ASBR is.
- **Type 5 (External)** — generated by ASBRs, floods the entire OSPF domain. Routes from outside.
- **Type 7 (NSSA External)** — like Type 5 but stays inside an NSSA until the ABR converts it.

### Timers
- **Hello interval**: 10s on broadcast/P2P, 30s on NBMA.
- **Dead interval**: 40s on broadcast, 120s on NBMA. Always 4× Hello.
- **Hello and Dead intervals MUST match** between neighbors — mismatch = no adjacency, full stop.
- **SPF delay**: 5s default (wait before recalculating after a change).
- **SPF holdtime**: 10s default (minimum gap between recalcs).
- **LSA retransmit**: 5s default.

### Neighbor states — the matchmaking ladder
Like the connection handshake in an Apex Legends lobby, two routers walk through states until they're "Full":

1. **Down** — no Hellos received.
2. **Attempt** — NBMA-only; manually configured neighbor not yet responding.
3. **Init** — saw a Hello, but the other side hasn't seen mine yet.
4. **Two-Way** — bidirectional confirmed. **DR/BDR election happens here.** On a multi-access segment, non-DR/BDR routers stop here with each other.
5. **ExStart** — master/slave negotiation for DBD sequence numbers.
6. **Exchange** — trading DBDs.
7. **Loading** — sending LSRs and LSUs to fill in missing pieces.
8. **Full** — LSDBs synchronized. **Only Full neighbors exchange routes.**

### DR/BDR election
On multi-access networks (Ethernet), electing one router to be the source of truth prevents N² adjacencies — like picking one raid leader in a Helldivers 2 squad instead of everyone shouting orders simultaneously.

- **Priority first** (range 0–255, default 1), **Router ID as tiebreaker**.
- **Priority 0** = "I refuse to be DR or BDR, ever."
- **No preemption**: once elected, the DR stays DR until it dies or the process resets. A new high-priority router showing up doesn't dethrone it.
- **Point-to-point links skip the election entirely** — there's only two routers, no point.

### Router ID
- Manually set with `router-id`, or
- Highest IP on a **loopback** interface, or
- Highest IP on any active interface.
- Changes don't take effect until you restart the OSPF process (`clear ip ospf process`).

### Configuration gotchas
- **Process ID is locally significant** — Router A can run OSPF process 1 and Router B can run process 47; they'll still peer fine.
- **`network` statements use wildcard masks**, not subnet masks. Wildcard is the bitwise inverse: 255.255.255.0 → 0.0.0.255.
- **Per-interface cost override**: `ip ospf cost <value>`.
- **Global reference bandwidth tweak**: `auto-cost reference-bandwidth <Mbps>` — do this consistently on every router or your costs won't match across the topology.
