# Routing Fundamentals

## What it is

In Pokemon, you can't fly directly from Pallet Town to the Indigo Plateau on day one. You hop Route to Route, town to town, and at each Pokemon Center the nurse points you toward the next gym. Nobody hands you the whole itinerary — each stop only knows the next leg. That's exactly what routing does — every router along the path knows just enough to forward your packet one hop closer.

**Routing** is the process by which a device builds a *routing table* (its personal map of the network) and forwards packets based on it. The routing table is just a list of instructions: "if the destination looks like X, send it that way."

The key split:

- **Same subnet?** No router involved. Your computer wraps the packet in a frame addressed directly to the destination host's MAC. Packet destination IP = host's IP. Frame destination MAC = host's MAC. Done. Like trading Pokemon with the kid standing next to you in the Pokemon Center — no Routes required.
- **Different subnet?** Your computer can't reach the destination directly, so it hands the frame to its **default gateway** — the router on its subnet. Packet destination IP is still the *final* destination, but the frame destination MAC is the *gateway's* MAC. The host is basically saying "I don't know how to get to Cinnabar Island, Professor Oak, you handle it."

Hosts never frame packets directly to remote hosts. Ever. If the destination isn't on the local subnet, the frame goes to the gateway, period.

## Why it matters

Without routing, the internet is just a pile of disconnected LAN parties. Routing is what stitches every network together. It's also where most "why can't I reach this server" problems live — a missing route, a wrong gateway, a packet hitting a router with no entry that matches and getting silently dropped like an unranked queue dodge.

Understanding the IP-stays-the-same / MAC-changes-every-hop dance is the single biggest "aha" in networking. The packet's destination IP is its true destination, written in stone for the whole trip. The frame's destination MAC only describes the *next hop* and gets rewritten at every router. It's like a relay race where the baton (IP) is the same the whole way, but the runners (MACs) keep swapping.

## Key facts

### How a router processes a frame

When a frame hits a router interface:
1. Strip the Ethernet header (the runner drops the baton handoff wrapper).
2. Look at the destination IP in the packet.
3. Look it up in the routing table.
4. **Forward** it (most cases), **receive** it (the packet was for the router itself), or **drop** it (no match found anywhere).

Routers never flood. Unlike a switch hitting an unknown MAC and broadcasting out every port, a router with no matching route just kills the packet. No match, no mercy.

### Route types in the table

- **Connected route (C)** — a network directly attached to an up/up interface. The router learned about it just by having that interface configured and online.
- **Local route (L)** — the router's own interface IP, stored as a `/32` host route. It's how the router recognizes "hey, that's me."
- **Network route** — prefix less than `/32`, covers a range of addresses (e.g., `10.0.0.0/24`).
- **Host route** — prefix exactly `/32`, covers a single IP.

### Longest prefix match

When multiple routes could match a destination, the router picks the **most specific** one — the longest prefix wins. It's loot rarity in Tarkov: a `/32` is a red keycard match, a `/24` is purple, a `/16` is blue, and `/0` is the gray default that matches anything when nothing better is around.

`/32` > `/24` > `/16` > `/0`

Outcomes:
- Match a non-local route → forward to next hop.
- Match a local route → router consumes the packet.
- No match → drop.

### Layer 3 vs. Layer 2 matching

- **Layer 3 (routing):** longest-prefix IP match. Fuzzy, hierarchical.
- **Layer 2 (switching):** exact MAC match. Binary, no concept of "close enough."

### Static routing

Static routes are manually configured. You're hand-writing the GPS instead of letting it auto-update — predictable, but you eat the maintenance.

Only routes to source and destination networks need to exist. You don't need to map the entire internet, just the relevant networks for traffic to flow both ways.

**Recursive static route** — give the router a next-hop IP, and it looks up *that* IP in its own table to figure out which interface to use. One extra lookup step.
```
ip route <network> <mask> <next-hop-ip>
```

**Directly connected static route** — specify an exit interface instead of a next-hop IP. Sounds clean but relies on **proxy ARP** to actually work, which is fragile and considered bad practice. Avoid.

**Fully specified static route** — both exit interface *and* next-hop IP. No recursion, no proxy ARP, no drama. The gold standard when you need a static route on a multi-access link.
```
ip route <network> <mask> <exit-interface> <next-hop>
```

### Default route

The `0.0.0.0/0` route — the catch-all. Matches every possible IP, but because it's `/0` (the shortest possible prefix), longest-prefix-match guarantees it's only used when nothing else matches. It's the "if all else fails, throw it that way" rule.

```
ip route 0.0.0.0 0.0.0.0 <next-hop>
```

### What changes hop-to-hop, what doesn't

- **Destination IP**: never changes. Same from source to final destination.
- **Destination MAC**: rewritten at every router. Always points to the *next* hop, never the final destination (unless the next hop *is* the final destination).

When forwarding to a next hop, the router builds a new frame with the next hop's MAC as the destination MAC. If it doesn't know that MAC yet, it ARPs for it.

### ARP's role

ARP is how a device learns "what MAC goes with this IP" on the local subnet.
- A host needing to talk to another host on the same subnet ARPs for the destination's MAC.
- A host needing to talk off-subnet ARPs for the **default gateway's** MAC — because the gateway is configured as an IP, not a MAC, and the host needs the MAC to build the frame.
